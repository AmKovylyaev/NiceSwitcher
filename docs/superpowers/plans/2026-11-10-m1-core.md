# M1: RU/EN-ядро и оценка — Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development. Одна задача на исполнителя, без дочерних агентов; основной агент лично проверяет diff и тесты по указанию пользователя.

**Goal:** Получить переносимое ядро, которое консервативно предлагает преобразование RU/EN, и воспроизводимую оценку baseline без изменения чужого текста.

**Architecture:** SwiftPM library `NiceSwitcherCore` без Cocoa/AX/SQLite/сети. Преобразование использует физические key codes и modifiers из ограниченного буфера, а таблицы вывода клавиш передаются извне с точным source ID. Примерные таблицы и маленький авторский корпус служат проверке pipeline, а не доказательством поддержки реальных input sources или финального качества.

**Tech Stack:** Swift 6, Foundation/XCTest, отдельный CLI `NiceSwitcherEvaluate`. Данные для исследовательского CLI читаются из явно указанного `Data/`; это не runtime-ресурсы готовой `.app`.

**Spec:** `docs/mac-layout-switcher-requirements.md`; утверждённый маршрут `docs/reviews/2026-11-10-implementation-review.md`.

## Global Constraints

- Основные языки — русский и английский; немецкий предусмотрен архитектурой на будущее.
- R5: сохранять смешанный RU/EN, сокращения, имена и технические термины. Не переводить смысл и не исправлять орфографию.
- При неоднозначности оставлять исходный ввод. Незнакомое слово само по себе не доказывает ошибку.
- Реальный source ID и modifiers обязательны. Не выдавать ручную QWERTY/ЙЦУКЕН-таблицу за проверенную macOS-раскладку.
- Текущее слово до 64 grapheme clusters; до четырёх предыдущих слов и до 256 Unicode scalars всего runtime-контекста. Нельзя после переполнения анализировать суффикс как новое слово.
- Исключения имеют приоритет; case-insensitive default. Никакого автоматического вечного blacklist.
- Пароли, secure input, неизвестное поле, URL/email/пути/код не анализируются. Проверка допустимой поверхности происходит адаптером ДО помещения символа в буфер; ядро получает только допущенные события.
- Paste/диктовка/IME и неподтверждённый физический ввод не превращаются в фиктивные key strokes. Composition/dead keys не угадываются.
- Ядро только возвращает предложение; не пишет в редактор, не переключает input source, не перехватывает Undo, не обучается на собственных решениях.
- Никаких внешних зависимостей/сетевых вызовов и пользовательских текстов в fixtures. Авторские примеры с явным происхождением.
- Цели финальной приёмки: ≤1 ложная замена на 1 000 корректных токенов и ≥90% исправлений однозначных поддерживаемых ошибок. Маленький синтетический корпус не доказывает достижение этих целей на пользовательском тексте.
- Исполнитель `gpt-6-luna`, reasoning `max`; проверка основным агентом.

## Review Focus

1. Неизвестный source ID/недостающая клавиша/несовпадающий исходный текст — отказ, без приблизительной транслитерации.
2. Переполнение или смена source ID в середине слова — отказ до границы, без обработки опасного хвоста.
3. Unicode и огромные grapheme clusters — отдельно считать graphemes/scalars/UTF-16; ограничить память.
4. Технический/смешанный/неоднозначный токен — отказ независимо от заманчивого кандидата.
5. Корпус: отсутствие пересечения групп tuning/held-out, валидные записи/ожидания, честные числители и знаменатели; запрет «улучшать» метрики пропуском неудобных примеров.

## Task 1: provenance, конвертер и ограниченный буфер

**Files:**
- Modify: `Package.swift` (добавить library/test target, не менять поведение Probe).
- Create: `Sources/NiceSwitcherCore/KeyboardLayout.swift`, `TypedToken.swift`, `TokenBuffer.swift`.
- Create: `Tests/NiceSwitcherCoreTests/KeyboardLayoutTests.swift`, `TokenBufferTests.swift`, `Fixtures.swift`.

**Interfaces:**
- `KeyModifiers: OptionSet, Hashable, Sendable`, portable flags shift/capsLock/option/command/control. Не использовать сырой Cocoa flags как portable значения.
- `KeyStroke: Hashable, Sendable { keyCode: UInt16, modifiers: KeyModifiers }`.
- `LayoutProfile { sourceID: String, outputs: [KeyStroke: String] }`; outputs только для одиночных committed символов без composition, не более 256 scalars на output. Source ID непустой. Некорректные profiles отклоняются throwing initializer.
- `TypedToken { text: String, sourceID: String, strokes: [KeyStroke] }`.
- `LayoutConverter.convert(_ token: TypedToken, from: LayoutProfile, to: LayoutProfile) -> String?`: исходные outputs в точности (UTF-16 elementsEqual, без нормализации документа) составляют token.text; использовать те же strokes/modifiers для target. Источник не совпал, output отсутствует, token/результат превышает лимиты или требуется неподдерживаемая композиция — nil. Командные/Control strokes не конвертируются. Никакой reverse mapping по приблизительному тексту.
- `TokenBuffer` с `appendCommitted(text: String, stroke: KeyStroke, sourceID: String)`, `finishWord() -> TypedToken?`, `reset()`, `invalidateCurrentWord()`, `context: [String]`. Лимиты фиксированы по Global Constraints. После переполнения, невалидного committed output или mid-word source change подавлять текущий токен до следующего finishWord. reset очищает всё; invalidateCurrentWord сохраняет только уже завершённый контекст и подавляет текущий токен. Завершённый контекст ограничен четырьмя словами и общим лимитом scalars с текущим словом.

- [ ] **Step 1: tests RED.** На fixtures `fixture.us`/`fixture.ru` проверить `ghbdtn → привет`, shifted `Ghbdtn → Привет`, обратное преобразование, различающиеся modifiers. Отдельно проверить unknown source/missing stroke/wrong source text/composition/command/control. Fixtures не используют настоящие Apple source IDs и явно подписаны как синтетические.
- [ ] **Step 2: реализовать интерфейсы, подтвердить GREEN.** Не добавлять macOS-зависимости или события ввода.
- [ ] **Step 3: buffer tests RED.** 64 grapheme допустимы, 65-й блокирует весь токен; один grapheme с >256 scalars блокируется; 65-й stroke тоже не накапливается; source change не выдаёт хвост; reset/invalidations работают; history ≤4 и total scalars ≤256 даже во время текущего слова. Boundary возвращает один token ровно один раз.
- [ ] **Step 4: реализовать ограниченный буфер и converter validation для прямого TypedToken.** Нельзя полагаться на то, что каждый токен обязательно пришёл из буфера.
- [ ] **Step 5: `swift test`, `swift build -c release`, `git diff --check`, коммит.** Полный отчёт `.superpowers/sdd/m1/task-1-report.md`, включая RED/GREEN и ограничения. Не объявлять реальные macOS input sources поддержанными.

## Task 2: консервативный детектор и исключения

**Files:**
- Create: `Sources/NiceSwitcherCore/Detection.swift`, `TokenProtection.swift`, `WordExceptions.swift`.
- Create: `Tests/NiceSwitcherCoreTests/DetectionTests.swift`, `TokenProtectionTests.swift`, `WordExceptionsTests.swift`.

**Interfaces:**
- Consumes: exact Task 1 interfaces.
- `WordExceptions.init(words: [String] = [])`, `contains(_ word: String) -> Bool`, mutating `add(_:)`/`remove(_:)`: явные слова с канонически нормализованным case-insensitive совпадением; оригинальный token не переписывается.
- `TokenSurface` enum: plainText/code/address/secure/unknown; только plainText допускается.
- `WordLexicon.init(frequencies: [String: [String: Int]]) throws`, `contains(_ word: String, sourceID: String) -> Bool`: source ID → словарь нормализованного слова с положительной integer frequency; некорректные частоты/пустые source IDs отклоняются.
- `CorrectionCandidate { original: String, replacement: String, targetSourceID: String }`.
- `DetectionDecision`: suggestion(CorrectionCandidate) либо abstain с перечислимой причиной.
- `Detector.decide(token: TypedToken, source: LayoutProfile, target: LayoutProfile, surface: TokenSurface, exceptions: WordExceptions, lexicon: WordLexicon) -> DetectionDecision`.
- Baseline: применять фильтры/исключения, затем conversion; если исходное слово известно в словаре любого из выбранных языков — abstain. Если кандидат неизвестен target-словарю — abstain. Если candidate == original или пуст — abstain. Только однозначный известный target и неизвестный source может дать suggestion. Это baseline без обещания персонализации или распознавания всех имён.

- [ ] **Step 1: tests RED.** Фильтры до детектора: любой непроверенный surface; URL/http/www/domain, email, slash/backslash/tilde paths, underscore/camelCase/code identifiers, digits, ALL CAPS, смешанные латиница/кириллица, emoji/контрольные символы/whitespace, длина <3. Знаки исходной раскладки, соответствующие буквам целевой, нельзя запрещать все сразу: отдельный тест `vj;yj → можно` при подтверждённых strokes и словаре; кандидат должен состоять из букв. Исключения с другим регистром/каноническим Unicode не исправляются. Не утверждать распознавание всех возможных паролей по самому слову.
- [ ] **Step 2: реализовать WordExceptions/TokenProtection и подтвердить GREEN.** Разумно консервативный отказ допустим; не отключать детектор для всех входов.
- [ ] **Step 3: tests RED.** `ghbdtn` с лицензированным тестовым словарём возвращает привет; reverse known target аналогично; обе правдоподобные формы — abstain; unknown original+unknown target — abstain; known original в любом выбранном языке — abstain; unknown profile и неверные strokes — abstain. Тесты правильных технических токенов из ТЗ.
- [ ] **Step 4: реализовать baseline и подтвердить GREEN.** Ни сетевых словарей, ни ML, ни mutable learning state.
- [ ] **Step 5: полный `swift test`, release build и diff check; коммит.** Отчёт `.superpowers/sdd/m1/task-2-report.md`. В отчёте явно назвать оставшиеся ограничения имен/контекста/реальных layouts.

## Task 3: корпус, оценка и отчёт baseline

**Files:**
- Modify: `Package.swift` (executable target), `README.md`.
- Create: `Sources/NiceSwitcherEvaluate/main.swift`, `Sources/NiceSwitcherCore/Evaluation.swift`.
- Create: `Tests/NiceSwitcherCoreTests/EvaluationTests.swift`.
- Create: `Data/Corpus/tuning.jsonl`, `Data/Corpus/held-out.jsonl`, `Data/Layouts/fixtures.json`, `Data/Lexicon/baseline.json`, `Data/README.md`, `provenance.json`, `THIRD_PARTY_NOTICES.md`.
- Create: `docs/validation/m1-baseline.md`.

**Interfaces:**
- Consumes: Task 1/2 signatures.
- `CorpusExample` Codable: id, groupID, category, split, text, expectedText (null для preserve), sourceID, targetSourceID, surface, strokes. sourceID и layouts используют только fixture profiles.
- `EvaluationDataset.load(dataDirectory: URL) throws -> EvaluationDataset`: загружает два JSONL splits, JSON profiles и lexicon, валидирует перед evaluation. `Data/Layouts/fixtures.json` содержит source IDs и entries (keyCode/modifiers/text), из которых строятся реальные `LayoutProfile`, без зависимости CLI от XCTest fixtures.
- `EvaluationSummary` Codable: total, correctTokens, errorTokens, falseCorrections, correctedErrors, missedErrors, wrongCorrections, abstentions, category counts, falseCorrectionRate, supportedErrorRecall. Нулевой знаменатель → null, не NaN/Infinity и не 100%.
- `CorpusValidator` отклоняет duplicate IDs/group leakage между splits, неизвестный split/source ID, пустые строки/массивы, некорректные strokes и ошибочные ожидания, expectedText == original для error. Ошибка данных завершает CLI ненулевым кодом вместо исключения строки из оценки.
- `NiceSwitcherEvaluate` локально загружает corpus/layout/lexicon fixtures из `Data/` по явному пути, выводит JSON и ничего не скачивает/не обучает. Параметры/лексикон фиксированы до held-out прогона. Command: `swift run NiceSwitcherEvaluate --data-dir Data`.

- [ ] **Step 1: tests RED для evaluation counts.** Пример с preserve, верной/ошибочной заменой, пропущенной ошибкой и abstain; сверить все числители/знаменатели и категории. Пустой корпус — ошибка, пустая категория — null rate. Ошибочная correction не считается исправленной ошибкой.
- [ ] **Step 2: tests RED для validator.** Duplicate IDs, group leakage, schema/source/stroke/expectation errors не должны тихо пропускаться.
- [ ] **Step 3: реализовать evaluation и validator, добиться GREEN.** Pipeline использует реальный Detector, не таблицу готовых ответов.
- [ ] **Step 4: авторские данные.** Минимум 20 tuning и 80 held-out записей из ≥6 категорий, все с уникальными IDs; группы вариантов одной пары только в одном split. Оба направления, имена/аббревиатуры/техтермины/смешанные токены/защищённые токены/однозначные ошибки/неоднозначные слова. Bootstrap corpus синтетический, нерепрезентативный; не называть его независимым пользовательским испытанием. Лексикон малый, авторский, с зафиксированным происхождением, покрывает демонстрационные слова; не подгонять после просмотра held-out результата.
- [ ] **Step 5: provenance и отчёт.** Все данные/таблицы авторские fixtures MIT; сторонних ресурсов пока нет. В notices прямо указать это и необходимость отдельного аудита перед заимствованием. Отчёт содержит точную команду/коммит/размеры splits, baseline counts/categories и ограничения, без заявления о достижении финальных показателей на пользовательском тексте. Достоверное машинное feedback, лицензированные production-словари и реальные source tables ещё не готовы.
- [ ] **Step 6: `swift test`, release build, CLI evaluation, diff check; коммит.** Отчёт `.superpowers/sdd/m1/task-3-report.md`. M1 может быть принят как инженерный baseline, но качество на независимом репрезентативном корпусе и живой macOS остаётся обязательной открытой проверкой M5.
